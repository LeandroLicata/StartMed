This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

StartMed is a surgery-management system (Spanish domain): OR scheduling, insurance
authorizations, material/blood-product requests, pre-anesthesia evaluation, patient
prep, and informed consents. Laravel 13 / PHP 8.3 / MySQL 8.4, Vite 8 + Tailwind 4,
PHPUnit 12. Code, comments, and domain names are in Spanish — follow that convention.

## Commands

```bash
composer run dev            # runs server + queue worker + pail logs + vite concurrently
php artisan serve           # server only (http://127.0.0.1:8000; Laragon vhost: http://startmed.test)
npm run dev                 # vite only

php artisan test                        # full suite (SQLite in-memory, see phpunit.xml)
php artisan test --filter=ModelosTest   # single test class/method
composer run test                       # clears config cache first, then runs tests

./vendor/bin/pint          # code formatter (Laravel Pint)

php artisan migrate:fresh --seed   # recreate dev DB from scratch
php artisan db:show                # list tables; db:table cirugia for columns/indexes
```

Dev DB is MySQL (`startmed`). Tests use SQLite `:memory:` and never touch dev data.
Seeder admin user: `admin` / `admin1234`.

## Architecture

This is a database-first Laravel app: the schema follows an existing data-model
design, not Laravel conventions. Understanding the schema conventions is essential
before touching models or migrations.

### Schema conventions (deliberate, do not "fix" to Laravel defaults)

- **Data-model naming, not Laravel.** Tables are `PascalCase` (`Cirugia`,
  `PedidoMaterial`), PKs are `idXxx`, columns are `camelCase`. `Persona` is the lone
  exception — it uses `snake_case` (kept from the original design).
- **No timestamps.** No table has `created_at`/`updated_at`; every model declares
  `public $timestamps = false`.
- **Soft deletes are manual.** `fechaBaja*` / `fechaHoraBaja*` columns mark deletion.
  Laravel's `SoftDeletes` trait is not used.
- **State via date ranges.** State tables (`CirugiaEstado`, `QuirofanoEstado`, …)
  record history with `fechaInicio*` / `fechaFin*` rather than overwriting a status
  column.
- **Explicit FK names** (`fk_<tabla>_<ref>`) — Laravel's autogenerated names exceeded
  MySQL's 64-char limit.
- **Windows lowercases table names** (`lower_case_table_names=1`): `Cirugia` is stored
  as `cirugia`. `php artisan db:table cirugia` works, `db:table Cirugia` does not.
  Columns keep their casing. This is case-insensitive on Windows/MySQL but **matters
  for a Linux deploy** — migrations and models must use one consistent string.

### Migrations

13 domain migrations (`2026_07_31_1001xx_…` through `…_101300`), one per module, each
creating its tables in dependency order and dropping them in reverse so
`migrate:rollback` stays clean. The three leading `0001_01_01_*` migrations are
Laravel scaffolding — of the default `users` migration, **only the `sessions` table
survives** (the DB session driver needs it); the `users` table was removed on purpose.

### Models

65 models in `app/Models/`, one per domain table, ~153 relations. **Relation names
derive from the FK column, not the target table**, so multiple FKs to the same table
don't collide — e.g. in `Cirugia`: `paciente()` (idPersonaPaciente→Persona),
`cirujano()` / `anestesista()` (idPersonal*→Personal). When adding relations, follow
this column-based naming.

`tests/Feature/ModelosTest.php` reflects over all 65 models and their relations,
asserting each table + PK exists, each relation compiles to SQL, and every referenced
column (FK, owner/local key, pivot) exists. **Adding a table without its model, or
renaming a column without updating the model, breaks this test** — it is the guardrail
for schema/model drift.

### Authentication

Login uses the domain `Usuario` table via a custom guard, **not** Laravel's `users`
table. `config/auth.php`: guard `web` → provider `usuarios` (eloquent) → model
`App\Models\Usuario`.

`Usuario` (extends `Authenticatable`) bridges the custom schema to the guard:
`getAuthPassword()` returns `passwordUsuario`; the `'passwordUsuario' => 'hashed'` cast
hashes on assignment; `getRememberTokenName()` returns `null` (no remember_token column,
so "remember me" is disabled). Login is by `nombreUsuario` with `throttle:6,1`, and
`LoginController` rejects users whose `fechaBajaUsuario` is set.

Password reset by email is **not** configured (`config/auth.php` `'passwords' => []`) —
`Usuario` has no email column; the address lives in `Personal.mailInstitucional` /
`Persona.contacto_email_direccion`, and the official channel hasn't been chosen yet.

### Routing / frontend

Routes are minimal (`routes/web.php`): `/` redirects to dashboard or login;
guest-only login routes; auth-only logout + dashboard view. Views are Blade in
`resources/views/`, assets bundled by Vite (`resources/css/app.css`,
`resources/js/app.js`) with Tailwind 4.
